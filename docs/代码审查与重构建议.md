## 一、总体判断

**结论：不需要重写，需要一轮"收敛型重构"。**

架构骨架是对的：`routes / modules / db` 三层清晰、SQL 全参数化无注入、迁移版本化、有几段质量很高的代码（流式下载解压、ZIP 路径防护、SMTP 错误分类重试、Cesium 资源清理）。

真正的债不是"设计错了"，而是**演进过程中同一个决定做了两遍**：

| 维度 | 做了一遍 | 又做了一遍 |
|---|---|---|
| 响应信封 | `{ok, message, data}`（52 处） | `{code, message, data}`（51 处） |
| 前端 API 层 | `api/dji.js`（axios） | `api/duav.js`（fetch） |
| 项目聚合逻辑 | `telemetry.js` 带缓存 | `session.js`、`model.js` 各抄一份无缓存 |
| 导航菜单 | `router/index.js` 的 `menuItems` | `AppShell.vue` 硬编码数组 |
| 时间格式化 | `utils/format.js` | 另外 8 处各写一遍 |
| ECharts 引入 | 2 处按需 | `StatsView` 全量 |

外加 4 个**已经坏了但还没被发现的**功能点，以及 3 个**安全口子**。这些是必须先处理的。

## 二、P0 — 会让服务崩溃或数据泄露（建议 1-2 天止血）

### P0-1. 48 个 async 路由裸奔，任一异常即进程退出

Express 4 不捕获 async handler 的 rejected promise，而项目里**没有任何错误中间件、没有 asyncHandler 包装器**（已验证：`grep "app.use((err"` 与 `Promise.resolve(fn` 均零命中）。

```js
// server/src/routes/ops.js:25
router.post('/snapshot/refresh', async (req, res) => {
  telemetry.invalidate();
  const snap = await telemetry.snapshot(true);   // 抛错 → 无人接管
  res.json({ ok: true, data: snap });
});
```

`telemetry.snapshot` 会遍历全部设备并发打司空 2，任一设备网络抖动 → unhandled rejection → **Node 进程终止**，整个 BFF 掉线，请求方永远挂起。

**改法**：加 `const wrap = (fn) => (req,res,next) => Promise.resolve(fn(req,res)).catch(next);`，配合统一错误中间件。这是**唯一一个"改一处、48 个路由同时受益"**的杠杆点，建议第一个做。

### P0-2. 模型路由路径穿越（可读取服务器任意文件）

```js
// server/src/routes/model.js:771-774
const dir = path.join(CACHE_ROOT, id);      // ← id 未校验
const target = path.resolve(dir, rel);
if (!target.startsWith(dir + path.sep)) return res.status(400)...
```

边界基准是 `dir`，而 `dir` 由未校验的 `id` 构造。`path.join(CACHE_ROOT, '../../../../etc')` 会规范化逃出根目录，此时 `startsWith(dir)` 恒为真 → 校验失效。实测 `id='../../../../etc'` 可越过 `CACHE_ROOT`。

命中目标包括 `data/tokens.json`（**明文 TK**）与 `.env`。

**改法**：`id` 加白名单 `/^[A-Za-z0-9_-]{1,64}$/`；边界基准改为 `CACHE_ROOT`；`realpath` 后再校验（代码注释声称做了 realpath，实际没调用）。

---

### P0-3. 全站无鉴权 + `/api/admin/proxy` 是开放 SSRF

`index.js:37-39` 全局中间件只有 `cors()` / `json()` / `urlencoded()`，无任何认证。`admin.js:23-36` 的 proxy 接受任意 `path`，配合 `session.endpoint === 'custom'` 可把请求打向任意内网地址，并用服务器保存的真实 TK 发请求。

**改法**：至少加一层 token 中间件；proxy 加 `/openapi/` 前缀白名单；`cors()` 改显式 origin。

## 三、P1 — 用户能感知的慢与架构收敛（建议 1 周）

### P1-1. Cesium 4.2MB 实际进了首屏，与注释完全相反

注释写"路由级懒加载，Cesium chunk 不进任何业务页首屏"，但 `manualChunks` 把公共代码 hoist 进 cesium chunk 后，入口 chunk **反向静态 import 它**（已验证）：

```html
<!-- dist/index.html -->
<link rel="modulepreload" href="/assets/cesium-C-GT5Q9D.js">   <!-- 4.06 MB -->
```
```js
// dist/assets/index-*.js
import{c as nl,g as al,_ as Un}from"./cesium-C-GT5Q9D.js";
```

首屏 JS 从 1.2MB 涨到 5.3MB。大屏、考勤页根本不需要 Cesium。

**改法**：去掉 `manualChunks` 对 cesium 的强制切分（两个使用方都是路由懒加载，天然会切成异步 chunk），或用 `modulePreload.resolveDependencies` 过滤。建议加一条 CI 断言：构建后若 `index.html` 出现 cesium modulepreload 则 fail——**防止这类"注释与实现背离"再次发生**。

### P1-2. 三处 N+1 查询，同步阻塞事件循环

最严重的一处在 `miscRepo.js:471`：先查 id 列表，再**逐条 `findById`**，`pageSize` 上限 500 → 最多 502 次查询。better-sqlite3 是同步 API，期间所有 SSE/HTTP 请求全部停顿。

另两处：`miscRepo.js:178`（架次列表）、`reviewService.js:280`（审核队列，2N+1）。

### P1-3. 大屏每 60s 全量销毁重建 Cesium 实体

`loadAll()` 无条件 `rebuildEntities()`（`removeAll()` 后重建 21 市立体块 + 描边 + 标注 + 设备实体），无 diff、无页面可见性守护。大屏常挂值班室不关标签页，每分钟一次全量重建 + 图表 `setOption(notMerge)` 全量重绘。

**改法**：数据更新走增量 diff（只改 `material`/`extrudedHeight`）；轮询加 `visibilitychange` 守护；抽 `usePolling(fn, interval)` 统一收编全项目 6 处定时器。

### P1-4. 统一两端契约（改动面最大，收益也最大）

- **后端响应信封**：`{ok}` 与 `{code}` 对半开，错误码无集中表，且多处"业务失败但 HTTP 200"。抽 `ok()/fail()` 到 `src/http.js`。
- **前端 API 层**：`dji.js` 成功返回裸 `data`、失败返回 `{ok:false}`，**形状不对称**；`duav.js` 另起一套 fetch。统一到 axios 并恢复对称性（破坏性改动，需同步改所有 `if (r?.ok)` 调用点）。
- **吉林一号底图 key 明文进产物**（`BaseMap.vue:86` 的 `mk`/`tk`），应移到后端代理。
