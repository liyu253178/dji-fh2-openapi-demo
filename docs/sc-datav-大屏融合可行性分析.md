# sc-datav 与本平台首页大屏融合 · 可行性分析

> 结论先行：**技术上可行，但「整仓融合」是错的，正确的做法是「抄视觉壳，不搬代码」。**
> 建议工作量：视觉增强 **1~2 天**，能看到明显提升；整仓融合 **3~5 天**，且会把 Vue 栈变成 Vue+React 双栈。

分析依据：2026-09-30 实测 sc-datav 仓库源码、依赖与许可，以及本平台 `DashboardView.vue` / `BaseMap.vue` 的现状。

---

## 一、先把 sc-datav 看清楚（实测结论）

| 项 | 实测结果 |
|---|---|
| License | **Apache-2.0**（可商用，但**必须保留作者署名与 NOTICE**） |
| 框架 | React 19.1 + TypeScript + Vite 8 + styled-components |
| 3D | three 0.183 + @react-three/fiber 9 + drei 10 + postprocessing |
| 图表 | ECharts **6.0**（我们是 5.5） |
| 地理 | `d3-geo` + `topojson-client`，**不接任何底图瓦片服务** |
| 地图实现 | `sc.json`（四川轮廓 GeoJSON，277KB）→ `d3-geo` 投影 → `THREE.Shape` → `ExtrudeGeometry` 拉伸成 3D 地块，贴 `sc_map.png` / `sc_normal_map.png` / `sc_displacement_map.png` 三张贴图做质感 |
| 数据 | 全部写死在 `stores/`、`cityData.ts`、`heatmapData.json`，**没有任何接口调用** |
| 规模 | 源码 91 个文件，4 个 Demo 页（demo0 省域 / demo1 城市 / demo2 / demo3） |

**它是一套「美术模板」，不是地图引擎。** 它之所以敢不做底图，是因为它只画**一个行政区的轮廓**——省界是封闭多边形，拉伸成块状即可，不需要瓦片、不需要坐标纠偏、不需要任意缩放。

## 二、我们的大屏现状

`web/src/views/DashboardView.vue`（511 行）当前是：

```
BaseMap（Leaflet + 高德瓦片，WGS84→GCJ02 纠偏）
├── 左上：近 7 天作业记录 + 本月航线执行柱状图（ECharts 按需引入）
├── 右上：选中机巢实时状态（真高/电量/RTK/温湿度/机场模式）
└── 底部：今日架次 / 累计时长 / 巡查里程 / 待处理告警
```

技术上：Vue 3.5 + Vite 5.4 + Leaflet 1.9 + ECharts 5.5 + three 0.186（three 只用在模型库与座舱）。

**我们的地图是真地图**：真实经纬度、真实瓦片、能落到具体街道和院子（工单派发、图斑定位都依赖这个精度）。

## 三、能不能融合：分三个层面看

### 层面 1：技术栈兼容性 —— ❌ 不兼容，且不该兼容

| 冲突点 | 说明 |
|---|---|
| **React 19 vs Vue 3** | 没有渐进式互操作。要在同一页面共存，只能引 React + ReactDOM 双运行时，或用 qiankun/single-spa 做微前端 |
| **ECharts 6 vs 5.5** | 大版本差异，API 有 breaking change |
| **Vite 8 vs 5.4** | 不能直接合 |
| **styled-components / zustand / leva** | React 生态，全都要额外引入 |

单为一个页面引入第二套框架 + 第二套构建链，**收益远小于成本**。

### 层面 2：地图能力 —— ❌ 不匹配，本质冲突

| 维度 | sc-datav | 我们 |
|---|---|---|
| 地图类型 | 单一行政区轮廓（封闭多边形拉伸） | 真实地理瓦片地图 |
| 坐标 | d3-geo 平面投影，无投影纠偏 | WGS84 ↔ GCJ-02 双向纠偏 |
| 精度 | 一省轮廓，缩放到市级就糊 | 可缩放到单栋建筑 |
| 交互 | 悬停显示省名/指标 | 点击机巢/图斑/工单，联动业务 |

**最要命的一点**：我们的业务闭环（工单派发、图斑定位、审核工作台、逆地理地址）全部依赖「真实坐标 ↔ 真实地理」的精确映射。一旦大屏换成「拉伸的行政区块」，**大屏看到的位置和其他页面看到的位置就对不上了**，用户会立刻发现「同一个机巢，大屏在市中心、座舱里在郊区」。

这不是美观问题，是**数据一致性问题**。

### 层面 3：视觉增强 —— ✅ 完全可行，且很值

它真正值钱的是**视觉语言**，不是地图：
- 描边发光 + 呼吸光晕的机巢标记
- 飞线动画（机场 → 作业点）
- 侧边扫光
- 数字滚动动画（`numberAnimation.tsx`）
- 面板边框/角标/科技感装饰件
- `autofit.js` 的屏幕自适应

这些**全部可以在我们的 Vue + Leaflet 技术栈里复现**，一行 React 都不用写。

## 四、推荐方案：抄壳不搬码

### ✅ 建议做（约 1~2 天）

| 改进项 | 实现方式 | 工作量 |
|---|---|---|
| **机巢标记升级** | 在 `BaseMap.vue` 的 `iconHtml()` 里给机场图标加 CSS 发光圈 + 呼吸动画（keyframes），保留真实坐标与底图 | 2h |
| **机场→作业点飞线** | Leaflet `L.polyline` + `dashArray` 动画；数据来自 `opsApi` 的近期任务，用 `taskLine` 折线 | 3h |
| **KPI 数字滚动** | 抄 `numberAnimation` 思路，写一个 20 行的 Vue 指令 `v-count`，替代直接赋值 | 1h |
| **大屏自适应** | 用 CSS `clamp()` + `vw` 替代 autofit.js，按 1920×1080 基准等比缩放 | 2h |
| **面板科技感** | 角标/描边/装饰线，纯 CSS | 2h |
| **告警呼吸点** | 待处理告警 > 0 时 KPI 单元格加脉冲红光 | 1h |

全部在现有 `DashboardView.vue` + `BaseMap.vue` 内完成，**零新增依赖，零框架风险**。

### ⚠️ 需要评估后再决定（约 3~5 天）

如果客户明确要「领导汇报用的省域态势大屏」，可以**另建一个独立页面** `/screen`，用纯 three.js（不用 React）复刻 sc-datav 的省域拉伸效果：

- 单独路由，独立入口，从大屏顶部加一个「汇报模式」按钮
- 用 `topojson-client` + `d3-geo` 加载**目标行政区** GeoJSON（需要客户提供当地 geojson，或从高德/DataV  atlas 拿）
- 省级指标 = 我们已有的 `/api/ops/overview`（架次/里程/在线率）+ `/api/ticket/stats/*`
- **不与大屏共用地图**，避免两套坐标体系并存

前置条件：**客户能提供行政区边界 geojson**，且**确实有汇报场景**。缺任何一个都别做。

### ❌ 不建议做

- 整仓 fork sc-datav 改数据
- 在 Vue 项目里引 React（qiankun 微前端）
- 用它的地图替换 BaseMap
- 把它当「技术栈更先进」的理由——它是 Vite 8 + React 19 没错，但那是另一个生态，不是更高维

## 五、对比总表

| 方案 | 工作量 | 风险 | 视觉提升 | 数据一致性 | 推荐 |
|---|---|---|---|---|---|
| 整仓融合（React + 我们的数据） | 3~5 天 | **高**（双框架/双构建/ECharts 6） | 高 | ❌ 地图精度冲突 | ❌ |
| 换掉 BaseMap 用它的地图 | 2~3 天 | **高**（业务坐标全乱） | 中 | ❌ **不可接受** | ❌ |
| 独立汇报页（纯 three 复刻省域） | 3~5 天 | 中（需客户 geojson） | 很高 | ✅ 独立不冲突 | ⚠️ 看客户需求 |
| **抄视觉壳，复用现有地图** | **1~2 天** | **低** | **中高** | ✅ 完全一致 | ✅ **推荐** |

## 六、许可与归属提醒

Apache-2.0 允许商用，但：
1. **必须保留原项目署名**（README 或 NOTICE 里致谢 knight-L/sc-datav）
2. 若我们**直接复制了它的源码文件**（如 `numberAnimation.tsx` 的逻辑、面板装饰 CSS），需在文件头保留原版权声明
3. 若只是「参考思路后自己用 Vue 重写」，法律上更宽松，但**仍建议致谢**

建议做法：**只借鉴设计思路，代码全部自己写**，并在 README 加一行「首页大屏视觉参考了 sc-datav（Apache-2.0）」。这样最干净。

## 七、一句话回答

> **技术上可行，但不该「融合」，该「取经」。**
> 它的地图是美术道具（四川轮廓拉伸块），我们是真实地理地图，两者互斥；
> 它的视觉语言（飞线、扫光、数字滚动、面板质感）是好东西，
> 在我们现有 Vue + Leaflet 栈里用 1~2 天复现即可，零风险。
> 真要省域汇报大屏，另开一页纯 three 实现，别动现有大屏。
