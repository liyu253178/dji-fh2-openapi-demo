# 井字形航线算法：专家指导 → 落地实现对照

> 输入是客户/专家给出的四段算法结构；产出是平台里的三个模块。
> 本文逐条记录：**专家怎么说的 → 我们怎么做的 → 为什么这么做 / 与专家说法的差异在哪**。
> 回归脚本：`server/scripts/verify-grid-geometry.mjs`（纯数学，41 项）、`server/scripts/verify-wayline-kernel.mjs`（真实机队联调，46 项）。

## 一、基础参数解算：任务参数 → 飞行几何参数

### 专家给的核心公式链

```
相对航高    H = f · GSD / δ                    （f 焦距，δ 像元尺寸）
摄影基线    B_base = L_ground · (1 − O_forward)
航线间距    D_line = W_ground · (1 − O_side)
```

并指出：倾角 θ 会使实际覆盖范围变形，需按中心投影几何修正有效航高分量；
参数解算模块要保留**迭代调整接口**，为后续仿地飞行／重叠率动态修正留空间。

### 落地：`server/src/modules/wayline/cameraGeometry.js`

| 环节 | 实现 |
| --- | --- |
| GSD ↔ 航高 | `heightFromGsd / gsdFromHeight`。用**等效焦距 + 等效画幅**口径，δ = frameW / imageW（等效像元尺寸），因此不需要知道传感器物理尺寸。界面上「航高」与「地面分辨率」互为输入输出，给哪个算哪个。 |
| 有效覆盖范围 | `groundFootprint()`：针孔模型把影像四角投到地面，θ=0 时得到矩形，θ≠0 时得到沿倾斜方向拉长的**梯形**。对远端光线做了「不越过地平线」的限幅（MAX_RAY=88°）。 |
| L_ground / W_ground | `footprintMetrics()`：给定飞行方向与倾斜方向的夹角 ψ，返回纵深、横向跨度、面积，以及**平均宽度 meanWidth = 面积 / 纵深**——这才是倾斜时「横向覆盖取哪个值」的正确答案。 |
| B_base / D_line 反解 | `overlapRatio()` + `solveStep()`：**不用近似公式**，而是把 footprint 与「平移后的自身」做凸多边形求交，算出真实面积重叠比，再二分反解出刚好达到目标重叠率的步长。 |
| 迭代接口 | `makeHeightSolver()` 把「航高 → 一趟几何」封装成纯函数，仿地飞行时对每个航点重算即可，不改结构。 |

### 为什么要偏离字面公式

教科书公式 `B = L·(1−O)` 成立的隐含前提是：**矩形足迹、沿该方向平移时重叠面积随位移线性下降**。
倾斜摄影下足迹是梯形，近端窄远端宽，"横向覆盖" 在整个纵深上不是常数。此时：

- 用**最远端宽**算 → 窄那一侧直接漏拍（致命）；
- 用**最近端宽**算 → 保守到航带翻倍，效率很差；
- 只有**面积比**才等价于真实的影像重叠率。

所以本实现直接用面积比求解。这样有一个好处能被验证：
**正射（θ=0）时它会精确退化回专家给的公式**，回归里有这条断言（`spacing === textbookSpacing`、`base === textbookBase`，误差 < 0.6 m）。
也就是说我们不是换了一套公式，而是把这套公式推广到了它本来不适用的场景。

实测（M4TD 广角 24mm、100 m 航高、航向 80% / 旁向 70%）：

| 倾角 | 主航向 ψ=0° | 正交航向 ψ=90° |
| --- | --- | --- |
| 0°（正射） | 间距 45.0 m / 基线 22.5 m | 间距 45.0 m / 基线 22.5 m |
| 45°（倾斜） | 间距 93.1 m / 基线 44.3 m | 间距 68.3 m / 基线 62.1 m |

45° 时两个方向差 **26.6%** —— 这正是专家第三点强调的现象。

## 二、单方向航线生成：扫描线填充

### 专家给的流程

1. 旋转坐标系，使目标航向对齐 X 轴；
2. 沿 Y 以 D_line 等间距扫描，求扫描线与多边形边界的交点，成对成段；
3. 凹多边形：用射线交叉法判断线段中点是否在多边形内，剔除无效线段；
4. 反变换回原始坐标系。
  的工程折中：凹多边形可先取凸包，再在后期剔除冗余航点。

### 落地：`routePlanner.js` 的 `planAreaCore`

完全一致，且第 3 步做得更严一点：

- 不是「交点两两配对」，而是**排序后逐相邻段做中点内测**——某一段的中点落在多边形外就整段丢弃，并计入 `stats.dropped`；
- `polygonConcavityXY()` 会给出凹/凸判定，`useHull` 开关可用凸包（默认关闭：默认走精确裁剪，既不漏拍也不需要后期剔除）；
- 航带数用 `ceil(width / spacing)` 且**居中布带**，不会产生裁剪后为空的空带（这是踩过坑的结论，见文件头注释）。

回归断言：L 形凹多边形下**全部航点都在测区内**、**空缺区域不产生任何航点**。

## 三、井字形交叉：第二组为什么必须独立解算

### 专家的说法

> 由于相机固定倾角 θ，相机在航向方向和旁向方向的有效地面覆盖形状不同，
> 因此第二组航线的航线间距可能需要独立计算，而非简单沿用第一组的参数。

### 落地

`cameraGeometry.passGeometry()` 对每一遍分别调用，输入是
`ψ = 飞行方向 − 倾斜方位角`：

- **云台随航向（默认，`tiltFrame='heading'`）**：每一遍的 ψ 都是 0，两遍几何相同，间距相等。
  这是 DJI 航线任务的真实行为——`gimbalPitchRotateAngle` 是机体系角度，飞机转向 gimbal 跟着转。
  此时「间距相同」是物理事实，而不是偷懒沿用。
- **固定方位视角（`tiltFrame='world'`）**：ψ₂ = ψ₁ + 90°，两遍走同一张 footprint 的不同剖面，
  解算出的间距必然不同。规划结果里会给解释性告警并把两个数值都显示出来。

一句话：**我们没有写死「第二遍间距 = 第一遍」这个结论，而是让几何自己算出来**。
计算出来相同（正射/随机头云台）就相同，不同（倾斜 + 固定视角）就不同。

### 这一版怎么落地的

| 项 | 结果 |
| --- | --- |
| `planDoubleGrid()` | 两组各自带 `spacing` / `wpSpacing`，输出 `groups[2]`（方向、间距、片基、航带数）与 `geometry.passes[2]`（含footprint的纵深、横向、教科书对照值） |
| 航点预算 | 两遍共享预算（`budget = maxWaypoints / 2`），超限时两遍一起等比放宽并置 `adjusted`，不做静默拉大间距 |
| 界面 | 「倾斜航线」结果里直接显示**主航向间距 / 正交航向间距**，并在两值不同时说明原因 |

## 四、航点排序：井字形路径的连接策略

### 专家给的策略

1. 组内：奇数行正向、偶数行反向 → 之字形；
2. 组间：第二组从离第一组最近的端点接入；
3. 首尾可选插入 homePoint，末尾附加测区质心；
4. 多架次：按最大航程/续航切分为多个子序列，每个子序列一次完整起降循环。

### 落地：`pathSequence.js` + `planDoubleGrid`

| 策略 | 实现 | 备注 |
| --- | --- | --- |
| 组内之字 | `planAreaCore` 里 `strips.length % 2 === 1` 时整带 reverse | 原有逻辑，回归验证相邻航带首尾间距 ≤ 40 m |
| 组间最近接入 | `sequenceGroups()`：把第二组「正序」与「整组逆序」两种遍历都算一遍接入距离，取近的那个 | 整组逆序（航带顺序 + 带内方向同时反）仍是合法的之字遍历，不会破坏相邻带连接；结果里 `stats.links[].reversed` 与 `stats.transitionsM` 可核对 |
| 起飞点 / 质心 | `sequenceGroups({ homeXY, centroidXY })` | 默认为关，避免不经确认就在航线里多塞两个点 |
| 多架次 | `splitSorties({ maxLengthM, homeXY })` | 贪心切分；尾巴过短会并入上一架次**但前提是合并后不超续航**（电量算不过来比多一次起降严重）；`homeXY` 时每个架次首尾都回归起飞点，构成完整起降循环 |

KMZ 默认是完整路径；`params.sortieIndex` 可以只打包某一个架次（名称自动加「·第N架次」后缀）。
里程超过单架次上限时会给告警，提示按架次拆分执行。

## 六、还没做的三件事（诚实留白）

1. **仿地飞行**：迭代接口已就位（`makeHeightSolver`），但没有接 DEM/DSM 数据源，所以目前所有航点仍是同一相对航高。地形起伏大的测区，高处的实际重叠率仍会下降。
2. **多架次 KMZ 的多 Folder 写法**：现在一个 KMZ 只有一条 Folder；真实多架次上传是生成多个 KMZ（`sortieIndex`），没有验证过「一个 KMZ 里放多个 Folder」大疆是否接受。没验证过就不能说支持。
3. **智能摆动拍摄**（`smartObliqueEnable`）未启用，目前模板里显式置 0。
